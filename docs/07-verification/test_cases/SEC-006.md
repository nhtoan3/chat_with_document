## Mục tiêu

Log container (`api`, `worker`) và `qa_log` không chứa nội dung câu hỏi, câu trả lời hay văn bản tài liệu.

## Nhiệm vụ của agent

1. Thực hiện test **chỉ trên localhost**: web `http://localhost:5173`, API `http://localhost:8000` (các dịch vụ phụ cũng ở localhost). Không gọi môi trường AWS.
2. Lưu **mọi** artifact của test case này trong thư mục riêng `./test_reports/SEC-006/` (tính từ gốc repo). Chạy lại thì xóa thư mục cũ trước: `rm -rf test_reports/SEC-006`.
3. **Quay video** toàn bộ quá trình thực hiện test → `./test_reports/SEC-006/video.webm` (nhiều phiên thì `video-02.webm`, …).
4. **Chụp ảnh màn hình** làm bằng chứng tại mỗi bước có 📸 → `./test_reports/SEC-006/screenshots/NN-<mô-tả>.png`.
5. Lưu output lệnh, log và dữ liệu sinh ra vào `./test_reports/SEC-006/logs/` và `./test_reports/SEC-006/data/`.
6. **Tạo báo cáo** `./test_reports/SEC-006/report.md` theo [mẫu ở README §5](README.md#5-mẫu-báo-cáo-reportmd): kết quả từng bước, ảnh nhúng, liên kết video, kết luận ✅ Đạt / ❌ Không đạt / ⛔ Bị chặn.
7. Phần CLI: lưu script vào `./test_reports/SEC-006/steps.sh` (mẫu bên dưới) rồi chạy `node frontend/e2e/run-cli.mjs SEC-006 test_reports/SEC-006/steps.sh` từ gốc repo — công cụ tự quay video, chụp ảnh khi kết thúc mỗi bước `### ` và lưu log.
8. Không sửa mã ứng dụng để test đạt. Bước nào lỗi thì ghi lại và tiếp tục các bước độc lập còn lại; luôn thực hiện phần dọn dẹp.

## Điều kiện tiên quyết

- Stack local đang chạy (`make dev`), `check_stack` trong `frontend/e2e/lib.sh` báo OK (API `http://localhost:8000/healthz` và web `http://localhost:5173` phản hồi).
- Nên có `ANTHROPIC_API_KEY` để kiểm cả đường trả lời thành công; không có khóa vẫn kiểm được đường lỗi.

## Dữ liệu kiểm thử

- Chuỗi đánh dấu duy nhất `MARKER-<số ngẫu nhiên>` chèn vào câu hỏi
- Cụm văn bản có trong tài liệu mẫu: `Tạm ứng 30%`

## Các bước thực hiện

| # | Thao tác | Kết quả mong đợi | 📸 |
|---|---|---|---|
| 1 | Kiểm tra stack localhost và dọn dữ liệu | `Stack OK`; lệnh TRUNCATE thành công | 📸 |
| 2 | Nạp PDF mẫu | `ready: 3` | 📸 |
| 3 | Hỏi 2 câu có chứa chuỗi đánh dấu | 200 hoặc 503 (tùy có khóa API) | 📸 |
| 4 | Xuất log api và worker | File `data/containers.log` | 📸 |
| 5 | Tìm nội dung trong log | Cả 3 số đếm đều `0` | 📸 |
| 6 | Kiểm tra cột `qa_log` | Chỉ có `id, created_at, status, latency_ms, input_tokens, output_tokens, chunk_count` | 📸 |

## Script gợi ý (`steps.sh`)

```bash
#!/usr/bin/env bash
# SEC-006 — Không log nội dung câu hỏi, câu trả lời, tài liệu
# Chạy từ gốc repo: node frontend/e2e/run-cli.mjs SEC-006 test_reports/SEC-006/steps.sh
set -uo pipefail
source frontend/e2e/lib.sh

echo "### Bước 1: Kiểm tra stack localhost và dọn dữ liệu"
check_stack || exit 1
reset_data

echo "### Bước 2: Nạp PDF mẫu"
seed_samples; wait_idle 300

echo "### Bước 3: Hỏi 2 câu có chứa chuỗi đánh dấu"
M=MARKER-$RANDOM$RANDOM; echo $M > "$DATA_DIR/marker.txt"; ask "$M Điều khoản tạm ứng trong hợp đồng khung với ABC là gì?"; ask "$M Mức phạt khi chậm thanh toán là bao nhiêu?"

echo "### Bước 4: Xuất log api và worker"
"${COMPOSE[@]}" logs --no-color api worker > "$DATA_DIR/containers.log"; wc -l "$DATA_DIR/containers.log"

echo "### Bước 5: Tìm nội dung trong log"
M=$(cat "$DATA_DIR/marker.txt"); echo "marker: $(grep -c "$M" "$DATA_DIR/containers.log")"; echo "van_ban_tai_lieu: $(grep -c 'Tạm ứng 30%' "$DATA_DIR/containers.log")"; echo "cau_hoi: $(grep -c 'Mức phạt khi chậm' "$DATA_DIR/containers.log")"

echo "### Bước 6: Kiểm tra cột qa_log"
psql_q "SELECT column_name, data_type FROM information_schema.columns WHERE table_name = 'qa_log' ORDER BY ordinal_position;"
```

## Tiêu chí đạt

Ba số đếm ở bước 6 bằng 0 và `qa_log` không có cột văn bản.

Kết luận **⛔ Bị chặn** khi thiếu điều kiện tiên quyết (stack không chạy, thiếu khóa API, thiếu dữ liệu), không phải do lỗi của ứng dụng.
