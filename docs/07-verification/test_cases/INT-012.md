## Mục tiêu

Khi S3 không khả dụng, API trả 502 `storage_error` và không để lại bản ghi `documents` mồ côi.

## Nhiệm vụ của agent

1. Thực hiện test **chỉ trên localhost**: web `http://localhost:5173`, API `http://localhost:8000` (các dịch vụ phụ cũng ở localhost). Không gọi môi trường AWS.
2. Lưu **mọi** artifact của test case này trong thư mục riêng `./test_reports/INT-012/` (tính từ gốc repo). Chạy lại thì xóa thư mục cũ trước: `rm -rf test_reports/INT-012`.
3. **Quay video** toàn bộ quá trình thực hiện test → `./test_reports/INT-012/video.webm` (nhiều phiên thì `video-02.webm`, …).
4. **Chụp ảnh màn hình** làm bằng chứng tại mỗi bước có 📸 → `./test_reports/INT-012/screenshots/NN-<mô-tả>.png`.
5. Lưu output lệnh, log và dữ liệu sinh ra vào `./test_reports/INT-012/logs/` và `./test_reports/INT-012/data/`.
6. **Tạo báo cáo** `./test_reports/INT-012/report.md` theo [mẫu ở README §5](README.md#5-mẫu-báo-cáo-reportmd): kết quả từng bước, ảnh nhúng, liên kết video, kết luận ✅ Đạt / ❌ Không đạt / ⛔ Bị chặn.
7. Phần CLI: lưu script vào `./test_reports/INT-012/steps.sh` (mẫu bên dưới) rồi chạy `node frontend/e2e/run-cli.mjs INT-012 test_reports/INT-012/steps.sh` từ gốc repo — công cụ tự quay video, chụp ảnh khi kết thúc mỗi bước `### ` và lưu log.
8. Không sửa mã ứng dụng để test đạt. Bước nào lỗi thì ghi lại và tiếp tục các bước độc lập còn lại; luôn thực hiện phần dọn dẹp.

## Điều kiện tiên quyết

- Stack local đang chạy (`make dev`), `check_stack` trong `frontend/e2e/lib.sh` báo OK (API `http://localhost:8000/healthz` và web `http://localhost:5173` phản hồi).
- Test dừng container `s3` trong vài giây.

## Dữ liệu kiểm thử

- Không cần dữ liệu riêng.

## Các bước thực hiện

| # | Thao tác | Kết quả mong đợi | 📸 |
|---|---|---|---|
| 1 | Kiểm tra stack localhost và dọn dữ liệu | `Stack OK`; lệnh TRUNCATE thành công | 📸 |
| 2 | Dừng S3Mock | Container `s3` stopped | 📸 |
| 3 | Tải lên 1 PDF mẫu | HTTP 502, `code: "storage_error"` (hoặc item lỗi `storage_error` — ghi nhận đúng dạng trả về) | 📸 |
| 4 | Kiểm tra không có bản ghi mồ côi | `count = 0` ở cả `documents` và `ingestion_jobs` | 📸 |
| 5 | Bật lại S3Mock và thử lại | Container `s3` chạy; upload trả 202 `queued` | 📸 |

## Script gợi ý (`steps.sh`)

```bash
#!/usr/bin/env bash
# INT-012 — Lỗi lưu trữ S3 khi tải lên → 502 storage_error
# Chạy từ gốc repo: node frontend/e2e/run-cli.mjs INT-012 test_reports/INT-012/steps.sh
set -uo pipefail
source frontend/e2e/lib.sh

echo "### Bước 1: Kiểm tra stack localhost và dọn dữ liệu"
check_stack || exit 1
reset_data

echo "### Bước 2: Dừng S3Mock"
"${COMPOSE[@]}" stop s3

echo "### Bước 3: Tải lên 1 PDF mẫu"
upload "$FIXTURES/sample/Hop_dong_khung_ABC_2026.pdf"

echo "### Bước 4: Kiểm tra không có bản ghi mồ côi"
psql_q "SELECT (SELECT count(*) FROM documents) AS documents, (SELECT count(*) FROM ingestion_jobs) AS jobs;"

echo "### Bước 5: Bật lại S3Mock và thử lại"
"${COMPOSE[@]}" start s3; sleep 5; upload "$FIXTURES/sample/Hop_dong_khung_ABC_2026.pdf"
```

## Tiêu chí đạt

Bước 3 trả 502 `storage_error`, bước 4 không có bản ghi, bước 5 tải lên lại thành công.

Kết luận **⛔ Bị chặn** khi thiếu điều kiện tiên quyết (stack không chạy, thiếu khóa API, thiếu dữ liệu), không phải do lỗi của ứng dụng.

## Dọn dẹp sau test

- Đảm bảo `s3` đã chạy lại
- `reset_data`
