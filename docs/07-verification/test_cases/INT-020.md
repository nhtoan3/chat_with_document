## Mục tiêu

Khi CSDL không khả dụng, API trả problem+json `internal_error` (500), không có traceback hay đường dẫn nội bộ.

## Nhiệm vụ của agent

1. Thực hiện test **chỉ trên localhost**: web `http://localhost:5173`, API `http://localhost:8000` (các dịch vụ phụ cũng ở localhost). Không gọi môi trường AWS.
2. Lưu **mọi** artifact của test case này trong thư mục riêng `./test_reports/INT-020/` (tính từ gốc repo). Chạy lại thì xóa thư mục cũ trước: `rm -rf test_reports/INT-020`.
3. **Quay video** toàn bộ quá trình thực hiện test → `./test_reports/INT-020/video.webm` (nhiều phiên thì `video-02.webm`, …).
4. **Chụp ảnh màn hình** làm bằng chứng tại mỗi bước có 📸 → `./test_reports/INT-020/screenshots/NN-<mô-tả>.png`.
5. Lưu output lệnh, log và dữ liệu sinh ra vào `./test_reports/INT-020/logs/` và `./test_reports/INT-020/data/`.
6. **Tạo báo cáo** `./test_reports/INT-020/report.md` theo [mẫu ở README §5](README.md#5-mẫu-báo-cáo-reportmd): kết quả từng bước, ảnh nhúng, liên kết video, kết luận ✅ Đạt / ❌ Không đạt / ⛔ Bị chặn.
7. Phần CLI: lưu script vào `./test_reports/INT-020/steps.sh` (mẫu bên dưới) rồi chạy `node frontend/e2e/run-cli.mjs INT-020 test_reports/INT-020/steps.sh` từ gốc repo — công cụ tự quay video, chụp ảnh khi kết thúc mỗi bước `### ` và lưu log.
8. Không sửa mã ứng dụng để test đạt. Bước nào lỗi thì ghi lại và tiếp tục các bước độc lập còn lại; luôn thực hiện phần dọn dẹp.

## Điều kiện tiên quyết

- Stack local đang chạy (`make dev`), `check_stack` trong `frontend/e2e/lib.sh` báo OK (API `http://localhost:8000/healthz` và web `http://localhost:5173` phản hồi).
- Test dừng container `postgres` trong vài giây.

## Dữ liệu kiểm thử

- Không cần dữ liệu riêng.

## Các bước thực hiện

| # | Thao tác | Kết quả mong đợi | 📸 |
|---|---|---|---|
| 1 | Kiểm tra stack localhost | `Stack OK` | 📸 |
| 2 | Dừng PostgreSQL | Container `postgres` stopped | 📸 |
| 3 | Gọi GET /documents | HTTP 500, `application/problem+json`, `code: internal_error` | 📸 |
| 4 | Tìm dấu vết kỹ thuật trong response | `0` dòng chứa `Traceback`, `File "`, `asyncpg`, `/app/` | 📸 |
| 5 | Bật lại PostgreSQL | `postgres` healthy; `/api/v1/documents` trả 200 | 📸 |

## Script gợi ý (`steps.sh`)

```bash
#!/usr/bin/env bash
# INT-020 — Lỗi không lường trước → 500 internal_error, không lộ stack trace
# Chạy từ gốc repo: node frontend/e2e/run-cli.mjs INT-020 test_reports/INT-020/steps.sh
set -uo pipefail
source frontend/e2e/lib.sh

echo "### Bước 1: Kiểm tra stack localhost"
check_stack || exit 1

echo "### Bước 2: Dừng PostgreSQL"
"${COMPOSE[@]}" stop postgres

echo "### Bước 3: Gọi GET /documents"
curl -sS -i "$API_URL/api/v1/documents" | tee "$DATA_DIR/resp.txt"

echo "### Bước 4: Tìm dấu vết kỹ thuật trong response"
grep -ciE 'traceback|File "|asyncpg|/app/' "$DATA_DIR/resp.txt" || true

echo "### Bước 5: Bật lại PostgreSQL"
"${COMPOSE[@]}" start postgres; for i in $(seq 1 30); do curl -fsS "$API_URL/api/v1/documents" >/dev/null && break; sleep 2; done; counts
```

## Tiêu chí đạt

Bước 3 trả 500 `internal_error` và bước 4 đếm được 0.

Kết luận **⛔ Bị chặn** khi thiếu điều kiện tiên quyết (stack không chạy, thiếu khóa API, thiếu dữ liệu), không phải do lỗi của ứng dụng.

## Dọn dẹp sau test

- Đảm bảo `postgres` đã chạy lại

## Ghi chú

- Nếu API trả mã khác 500 (ví dụ 503) với `code` hợp lệ trong `ERRORS`: ghi nhận, kết luận Đạt có ghi chú.
