## Mục tiêu

Câu hỏi sau khi trim phải dài 1–2000 ký tự.

## Nhiệm vụ của agent

1. Thực hiện test **chỉ trên localhost**: web `http://localhost:5173`, API `http://localhost:8000` (các dịch vụ phụ cũng ở localhost). Không gọi môi trường AWS.
2. Lưu **mọi** artifact của test case này trong thư mục riêng `./test_reports/INT-015/` (tính từ gốc repo). Chạy lại thì xóa thư mục cũ trước: `rm -rf test_reports/INT-015`.
3. **Quay video** toàn bộ quá trình thực hiện test → `./test_reports/INT-015/video.webm` (nhiều phiên thì `video-02.webm`, …).
4. **Chụp ảnh màn hình** làm bằng chứng tại mỗi bước có 📸 → `./test_reports/INT-015/screenshots/NN-<mô-tả>.png`.
5. Lưu output lệnh, log và dữ liệu sinh ra vào `./test_reports/INT-015/logs/` và `./test_reports/INT-015/data/`.
6. **Tạo báo cáo** `./test_reports/INT-015/report.md` theo [mẫu ở README §5](README.md#5-mẫu-báo-cáo-reportmd): kết quả từng bước, ảnh nhúng, liên kết video, kết luận ✅ Đạt / ❌ Không đạt / ⛔ Bị chặn.
7. Phần CLI: lưu script vào `./test_reports/INT-015/steps.sh` (mẫu bên dưới) rồi chạy `node frontend/e2e/run-cli.mjs INT-015 test_reports/INT-015/steps.sh` từ gốc repo — công cụ tự quay video, chụp ảnh khi kết thúc mỗi bước `### ` và lưu log.
8. Không sửa mã ứng dụng để test đạt. Bước nào lỗi thì ghi lại và tiếp tục các bước độc lập còn lại; luôn thực hiện phần dọn dẹp.

## Điều kiện tiên quyết

- Đã tạo virtualenv backend (`make venv`).
- Docker Desktop đang chạy (Testcontainers tự dựng PostgreSQL + pgvector cho test tích hợp).
- Stack local đang chạy (`make dev`), `check_stack` trong `frontend/e2e/lib.sh` báo OK (API `http://localhost:8000/healthz` và web `http://localhost:5173` phản hồi).

## Dữ liệu kiểm thử

- Không cần dữ liệu riêng.

## Các bước thực hiện

| # | Thao tác | Kết quả mong đợi | 📸 |
|---|---|---|---|
| 1 | Chạy test tự động `tests/integration/test_ask.py::test_invalid_question` (Testcontainers) | passed, exit code 0 | 📸 |
| 2 | Kiểm tra stack localhost và dọn dữ liệu | `Stack OK`; lệnh TRUNCATE thành công | 📸 |
| 3 | Hỏi chuỗi rỗng | HTTP 422, `code: question_invalid` | 📸 |
| 4 | Hỏi chuỗi chỉ có khoảng trắng | HTTP 422, `code: question_invalid` | 📸 |
| 5 | Hỏi chuỗi 2001 ký tự | HTTP 422, `code: question_invalid` | 📸 |
| 6 | Hỏi chuỗi đúng 2000 ký tự (chưa có tài liệu) | **Không** phải 422; nhận 409 `no_documents` (đã qua bước kiểm tra độ dài) | 📸 |

## Script gợi ý (`steps.sh`)

```bash
#!/usr/bin/env bash
# INT-015 — Câu hỏi rỗng / quá dài → 422 question_invalid
# Chạy từ gốc repo: node frontend/e2e/run-cli.mjs INT-015 test_reports/INT-015/steps.sh
set -uo pipefail
source frontend/e2e/lib.sh

echo "### Bước 1: Chạy test tự động tests/integration/test_ask.py::test_invalid_question (Testcontainers)"
(cd backend && .venv/bin/pytest 'tests/integration/test_ask.py::test_invalid_question' -v)

echo "### Bước 2: Kiểm tra stack localhost và dọn dữ liệu"
check_stack || exit 1
reset_data

echo "### Bước 3: Hỏi chuỗi rỗng"
ask ''

echo "### Bước 4: Hỏi chuỗi chỉ có khoảng trắng"
ask '     '

echo "### Bước 5: Hỏi chuỗi 2001 ký tự"
ask "$(printf 'a%.0s' $(seq 1 2001))"

echo "### Bước 6: Hỏi chuỗi đúng 2000 ký tự (chưa có tài liệu)"
ask "$(printf 'a%.0s' $(seq 1 2000))"
```

## Tiêu chí đạt

Bước 3–5 trả 422 `question_invalid`; bước 6 trả 409 `no_documents`.

Kết luận **⛔ Bị chặn** khi thiếu điều kiện tiên quyết (stack không chạy, thiếu khóa API, thiếu dữ liệu), không phải do lỗi của ứng dụng.
